# 测试用例目录说明

这个目录用于沉淀可重复执行的人工/半自动测试用例，给后续所有改动做回归基线。

## 使用规则

- 每次开始修改前，先定位和阅读相关测试用例。
- 每次修改完成后，先执行所有**未被本次改动直接影响**的旧测试用例，确认没有误伤。
- 若本次修改直接影响某个旧测试用例覆盖的区域，则本轮先跳过该旧用例，原因写进 `claude-progress.txt`。
- 之后验证本次新内容；若没有现成用例，必须新增用例。
- 新增或修改测试用例后，必须再按该用例执行一次，确认用例本身可用。
- 前端测试默认使用手机环境验证，优先账号 `root / 123`。
- 若工具支持，优先启用移动设备仿真（移动端 viewport + mobile UA + touch + DPR）；仅缩小桌面窗口不能视为完整移动端验证。
- 发布版后端测试默认监听地址使用 `192.168.1.38`。
- 若验证发布版页面，必须先确认服务端 `index.html` 返回的资源 hash，再信浏览器结果。
- 若本次改动不涉及后端逻辑，仅在确实需要验证新的发布版二进制时才重新执行后端构建。
- 发布版验证优先复用同一个端口；只有旧进程无法清理或确有排查需要时，才临时换新端口。
- 测试记录、用例维护说明、补充备注默认使用中文；若本轮无额外坑点，记录尽量简短。
- 遇到滚动、吸顶、封面、软键盘、视口变化类问题时，记录中需明确当前是否为移动设备仿真；必要时注明“仍建议真实手机补测”。

## 推荐字段

每个测试用例文件建议包含：

- 用例 ID
- 标题
- 类型（回归 / 冒烟 / 发布验证 / 样式验证）
- 覆盖范围
- 跳过条件
- 前置条件
- 执行步骤
- 预期结果
- 维护说明

## 模板

- 新建测试用例时，优先复制 `testcases/TEMPLATE.md` 再按具体场景补充，别每次重新发明格式。
