# TC-FE-004 发布编辑器移动端卡片样式贴近示例图

- 类型：发布验证 / 样式回归 / 交互回归
- 覆盖范围：`Explore` 页面顶部发布编辑器的移动端卡片布局、日期栏、发布按钮、输入区与底部快捷操作区；当前实现位于 `web/src/components/MemoEditor/index.tsx`、`web/src/components/MemoEditor/components/EditorToolbar.tsx`、`web/src/components/MemoEditor/Toolbar/InsertMenu.tsx`、`web/src/components/PagedMemoList/PagedMemoList.tsx`
- 跳过条件：若本次改动直接修改了发布编辑器外层结构、日期栏、底部快捷按钮布局、编辑器高度或 `publish` 变体样式逻辑，则本用例先跳过旧预期回归，待新需求验证完成后更新本用例再补测

## 前置条件

- 已完成前端改动代码提交到工作区
- 已在 `web/` 运行 `pnpm lint`
- 若验证发布版：已按顺序执行 `pnpm release` -> 仓库根目录 `scripts/build.sh`
- 已按 `scripts/all_build.sh` 约定启动发布版服务，例如：仓库根目录执行 `bash scripts/all_build.sh -s`；其等价手动命令是在 `build/` 目录执行 `./memos --addr 192.168.1.38 --port 12345 --data ..\\run`（Windows 下对应 `memos.exe`）
- 准备接近手机环境的浏览器设备仿真；至少覆盖 `390x844` 级别视口，并尽量启用移动端 UA、触摸事件和 DPR
- 测试账号：`root / 123`

## 执行步骤

1. 访问 `http://192.168.1.38:12345`。
2. 若未登录，则使用 `root / 123` 登录。
3. 用 `curl http://192.168.1.38:12345` 检查首页 HTML，确认引用的是当前最新构建产物的 JS/CSS hash。
4. 在浏览器打开 `http://192.168.1.38:12345/explore`。
5. 定位页面顶部发布编辑器外层卡片，记录其实际类名、`border-radius`、宽度与顶部偏移。
6. 检查卡片头部日期区域，记录展示文本、字号、是否可点击编辑。
7. 检查右侧发布按钮的文案、背景色、圆角与可点击状态。
8. 检查正文输入区的最小高度、占位文案与卡片内边距，确认在手机视口下不会挤压到顶部操作区。
9. 检查底部两个快捷操作按钮，记录其尺寸、背景色、圆角和图标，确认它们位于卡片底部左侧且互不重叠。
10. 可选补充：点击右侧更多按钮，确认仍能打开菜单，不因样式调整失效。
11. 记录当前验证环境是否启用了移动设备仿真；若仅使用桌面缩窗验证，需在结果中标明限制。

## 预期结果

- 服务端返回的首页资源 hash 与当前构建产物一致。
- 浏览器实际加载的是最新 hash 对应的资源，而不是旧资源。
- 发布编辑器外层卡片位于封面下方，当前期望类名可包含 `rounded-[28px]`、`min-h-[270px]`、`max-w-2xl` 等关键样式。
- 目标卡片计算样式 `border-radius` 为明显大圆角，当前期望约为 `28px`。
- 日期区域显示为 `YYYY/MM/DD` 格式，位于卡片左上，视觉权重高于正文占位文案，且点击后仍可进入时间编辑。
- 发布按钮位于卡片右上，保持蓝底白字的小尺寸圆角按钮样式，圆角应明显小于满血胶囊按钮，不出现换行、遮挡或禁用态误判。
- 正文输入区在手机视口下具有足够留白和高度，底部快捷按钮不会压住输入内容。
- 底部两个快捷操作按钮为浅灰色方圆角块，尺寸接近且横向排列，视觉上接近示例图中的附件/更多入口。
- 若点击更多按钮，菜单仍能正常展开，上传、关联、定位与专注模式入口可用。

## 维护说明

- 若后续通过共享变量或响应式规则统一发布编辑器样式，可更新“当前期望类名”描述，但必须保留“检查计算样式”和“移动端布局”要求。
- 若浏览器资源和服务端首页 hash 不一致，优先重开浏览器上下文后再测。
