# TC-FE-003 笔记列表项间距收紧

- 类型：发布验证 / 样式回归
- 覆盖范围：`Explore` 与 `Home` 页面笔记列表项外层间距；当前实现位于 `web/src/pages/Explore.tsx`、`web/src/pages/Home.tsx`
- 跳过条件：若本次改动直接修改了列表项外层包装结构、时间轴布局、头像区宽度或卡片分组方式，则本用例先跳过旧预期回归，待新需求验证完成后更新本用例再补测

## 前置条件

- 已完成前端改动代码提交到工作区
- 已在 `web/` 运行 `pnpm lint`
- 若验证发布版：已按顺序执行 `pnpm release`；若确实需要验证新的发布版后端二进制，再执行仓库根目录 `scripts/build.sh`
- 已启动发布版服务，例如：`build/memos.exe --addr 192.168.1.38 --port 12345 --data ..\\run`
- 准备接近手机环境的浏览器设备仿真；至少覆盖 `390x844` 级别视口，并尽量启用移动端 UA、触摸事件和 DPR
- 测试账号：`root / 123`

## 执行步骤

1. 访问 `http://192.168.1.38:12345/explore`。
2. 若未登录，则使用 `root / 123` 登录。
3. 用 `curl http://192.168.1.38:12345` 检查首页 HTML，确认引用的是当前最新构建产物的 JS/CSS hash。
4. 定位前两条可见笔记的外层包装容器（特征：包含时间列、头像和卡片内容的整行容器）。
5. 记录第一条笔记外层容器的类名与 `margin-bottom`。
6. 记录第一条与第二条笔记卡片之间的实际纵向像素间距。
7. 如需补充验证，可切换到 `Home` 页面检查列表项间距是否也同步收紧。
8. 记录当前验证环境是否启用了移动设备仿真；若仅使用桌面缩窗验证，需在结果中标明限制。

## 预期结果

- 服务端返回的首页资源 hash 与当前构建产物一致。
- `Explore` 页面笔记外层容器当前期望类名可为 `mb-2.5 flex w-full items-start gap-2`。
- `Explore` 页面相邻两条笔记卡片的实际纵向间距约为 `10px`。
- 列表项收紧后，时间列、头像、正文卡片之间仍保持清晰可读，没有发生重叠或错位。
- 若补测 `Home`，其列表项间距也应较之前更紧凑，且不影响阅读。

## 维护说明

- 若后续通过共享组件、变量或响应式规则统一控制间距，可更新“当前期望类名”描述，但必须保留“实际纵向间距”验证。
- 若仅在桌面缩窗环境验证通过，不能直接等同于真手机结论。
